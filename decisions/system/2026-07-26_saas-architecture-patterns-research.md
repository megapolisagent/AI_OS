# Архитектура 21 успешного AI-native SaaS — паттерны и принципы

Три параллельных исследования: dev tools (7), клиентский сервис/вертикали (7),
контент/креатив/GTM (7). Полные разборы по каждому продукту с источниками —
в стенограмме сессии 2026-07-26 (не дублирую здесь дословно — только
таблица и синтез).

## Сводная таблица

| Продукт | Что видит пользователь | Единица ответственности | Внутри: агент/workflow/engine/сервис | Почему именно так |
|---|---|---|---|---|
| Sierra | Один брендированный агент, omnichannel | Task / Skill | Constellation of 15+ моделей + Skills + Supervisor (verification) | Высокая цена ошибки (клиент бренда) → нужен верификационный слой поверх генерации |
| Intercom Fin | Один AI-агент в чат-виджете | Procedure / Workflow / Custom Answer | 3-фазный движок: Refine→Generate→Validate | Explicit validate-перед-отправкой — прямое требование доверия в CS |
| Decagon | Один AI-консьерж | не названо явно (Agent Engineer конфигурирует) | Fine-tuned специализированные модели + оркестрация | «LLM — универсалы, workflow требует специалистов» (цитата компании) |
| Ada | Один агент, которым управляет бизнес | talker/thinker — невидимо пользователю | Reasoning Engine: talker (быстро) + thinker (глубоко) | Сложность сознательно спрятана, чтобы бизнес видел «одного агента» |
| Harvey | 4 отдельных именованных продукта (Assistant/Vault/Knowledge/Workflow Agents) | Tool Bundle; отдельный sub-agent для драфтинга | Один основной агент (tool-calling loop) + модульные bundles; Workflow Agents — отдельный детерминированный продукт | «Agents are the means; workflows are the ends» — осознанное разделение по риску задачи |
| Abridge | Вообще без «агента» — амбиентная документация | Стадия pipeline (ASR / генерация) | Линейный ASR→LLM pipeline, не агентно | Регуляторная/медицинская ответственность требует детерминированности и обязательной подписи врача, не автономии |
| Synthesia | Инструмент с режимами, без агента | Модель (EXPRESS-1, Dubbing 2.0) на функцию | Портфель отдельных генеративных моделей | Категория (генеративное медиа) не требует agent-фрейминга вообще |
| Cursor | Редактор + Agent mode + параллельные копии | не названо явно | Один ReAct-агент, параллелизуемый в изолированных копиях | Параллелизм решает throughput, не корректность — «multi-agent» маркетингово, не архитектурно |
| Replit | Один чат «Replit Agent» | Task (сознательно «наименьшая возможная задача» на агента) | Настоящий multi-agent: Manager/Editor/Verifier | Реактивный ответ на рост ошибок при множестве инструментов у одного агента; Verifier специально эскалирует, не решает сам |
| Cognition (Devin) | Один «AI software engineer» | не декомпозировано | Единый агент + инструменты (shell/editor/browser), публичный манифест против multi-agent | Суб-агенты теряют общий контекст — хуже качество (прямая противоположность Replit, та же категория) |
| Vercel v0 | Чат «текст→UI» | Стадия pipeline (RAG / генерация / AutoFix) | Композитный pipeline: RAG + генерация + детерминированный AutoFix | Измеримый прирост точности (93.87% vs 78.43% baseline) — инженерное, не агентное решение надёжности |
| Lovable | Чат с режимами Plan/Agent/Edit | Режим | Роутинг между LLM-провайдерами по задаче (не роли-агенты) | Философия «не строить под гипотетическое будущее» — простота как принцип |
| ElevenLabs | Голосовой агент + отдельный конструктор Agent Workflows | Два слоя: внутренний (невидим) / Workflow-узел (виден клиенту) | Внутри — оркестрация моделей одного агента; Workflows — настоящий multi-agent с subagents+handoff, но это фича для клиента | Различие «что скрыто как инфраструктура» vs «что отдано клиенту как настраиваемая способность» |
| Glean | Assistant + отдельный Agent Builder | «Expert/specialist agent», строится клиентом | Router + клиентские специализированные агенты, не фиксированный ростер компании | Разнообразие enterprise-кейсов требует расширяемости клиентом, не встроенного набора ролей |
| Perplexity | Один поисковый ассистент + отдельные брендированные поверхности (Comet, Labs, Enterprise) | Шаг внутри плана | Pipeline план→исполнение, модель-специфичные вызовы по шагам | Стандартный паттерн deep-research: отделить «что делать» от «делать» |
| Jasper | «100+ агентов» вокруг 5-стадийного pipeline | Agent = исполнитель скоуп-задачи; Pipeline = workflow; Jasper IQ = governance-слой | НЕ ЗНАЕМ архитектуру напрямую — вероятно шаблоны поверх роутера моделей, не 100 персистентных агентов | Governance/согласование перед публикацией — тот же мотив, что у CS-группы |
| Gamma | Один инструмент, без агент-брендинга вообще | не применимо | НЕ ЗНАЕМ, вероятно простой/малошаговый генеративный pipeline | Контрпример: $100M+ ARR без единой agent-концепции — не необходимое условие успеха |
| Runway | Прямой доступ к моделям ИЛИ «Runway Agent» ИЛИ «Media Router» (тот же слой, упакован для разработчиков) | «Модель» vs «Agent» (слой суждения/роутинга) | Единый оркестратор/роутер между взаимозаменяемыми генеративными моделями | Разные модели сильны в разном (движение/фотореализм/скорость) — роутер кодирует это знание |
| Clay | Табличный workflow-конструктор, Claygent построчно | Запись/строка — уникально среди всех 21 | Подтверждённый настоящий multi-agent: Research Agent → Execution Agent, цепочка | GTM-обогащение естественно распадается на «извлечь-структурировать» и «решить-действовать» — разные типы суждения |
| Writer | Agent Builder (клиент строит) + флагманский WRITER Agent | Agent = blueprint+interface; Workflow/Playbook = сохранённая политика; Action = вызов инструмента | Инфраструктура, где КЛИЕНТ выбирает единый оркестратор или настоящий multi-agent | Позиционирование как горизонтальная инфраструктура, не фиксированный продукт |
| Artisan (Ava) | Одна антропоморфная персона «Ava» | не раскрыто | НЕ ЗНАЕМ, вероятно единый оркестратор+инструменты под одной персоной | Негативный кейс: claim полной автономии → репутационный удар + практический откат к копайлоту |

## Принципы проектирования SaaS (не про технологии)

**1. Пользовательская единица доверия почти всегда одна, независимо от внутренней сложности.** Ни один успешный продукт не показывает пользователю «команду агентов, договаривающихся между собой» — даже там, где внутри реально работает несколько ролей (Ada, ElevenLabs), это спрятано. Простота фасада — почти универсальное требование продукта, сложность — вопрос реализации, не заявленный пользователю выбор.

**2. Настоящий multi-agent как решение самой компании о своём продукте — редкость, а не норма.** Из 21 продукта первоисточником подтверждён только у Clay и Replit. У большинства других multi-agent либо вообще отсутствует, либо существует как конфигурируемая фича, которую строит клиент (ElevenLabs Workflows, Glean Agent Builder, Writer) — сложность выталкивается на край системы, не остаётся в решении вендора о своём же продукте.

**3. Реальная единица ответственности почти всегда мельче, чем «агент».** Task, Skill, шаг плана, запись/строка, tool bundle, стадия pipeline — вот что на практике тестируется и на что можно положиться отдельно. «Агент» — обёртка для пользователя, не инженерная единица надёжности.

**4. Слой проверки/эскалации появляется там, где высока цена ошибки, а не потому что «так положено агентам».** Validate-фаза Fin, supervisor Sierra, thinker Ada, обязательная подпись врача у Abridge, разделение agentic/workflow у Harvey по риску задачи — всё это возникает именно в категориях с дорогой ошибкой (клиент, право, медицина). В категориях с дешёвой ошибкой (Gamma, Synthesia) об этом слое вообще не упоминается.

**5. Один и тот же вопрос архитектуры может иметь два противоположных верных ответа в одной категории.** Replit и Cognition — прямые конкуренты, одна и та же задача (AI-инженер), опубликованные инженерные обоснования, противоположные выводы, оба коммерчески успешны. Значит «правильной» архитектуры на уровне «агенты или нет» не существует само по себе — есть дисциплина последовательного исполнения выбранного пути.

**6. Слово «агент» в продуктовом брендинге не обязано соответствовать инженерной реальности.** «100+ агентов» Jasper, персона «Ava» у Artisan, «multi-agent» у Cursor (на деле — параллельные копии одного агента) — маркетинговый термин и архитектура расходятся регулярно. Gamma — контрдоказательство от противного: один из самых капитало-эффективных успехов выборки вообще без agent-брендинга.

**7. Claim о полной автономии — отдельный, более рискованный продуктовый выбор, чем сама архитектура.** Единственный явный негативный кейс выборки (Artisan) — не про технологию, а про несоответствие заявленной автономии реальной надёжности: репутационный удар и практический откат к копайлот-режиму. Эхо более раннего вывода этой же сессии про AI SDR (маркетинг-исследование, независимо).

**8. Самый частый паттерн — не «одна модель» и не «много агентов», а слой суждения/роутинга над взаимозаменяемыми моделями.** Sierra (constellation), Runway (Agent/Media Router), Perplexity (модель на шаг плана), вероятно Clay и Lovable — это встречается чаще, чем чистый монолит или чистый multi-agent, и заслуживает называться отдельной, третьей категорией, а не промежуточным случаем между двумя другими.

**9. Публичное инженерное обоснование коррелирует с прослеживаемой дисциплиной решения, но это не доказанная причинность.** Компании с сильным инженерным блогом (Vercel — конкретные цифры точности, Cognition — манифест, Replit — интервью с цитатами, Clay — интервью CEO) дают проверяемую архитектуру; там, где раскрытия нет (Gamma, Jasper, Artisan), реальность недоступна для проверки — маркирую как наблюдение исследовательского качества, не как архитектурный принцип с тем же весом, что 1-8.
