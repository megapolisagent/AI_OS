# Framing Drift и ассимиляция Blueprint Agent System

## Источник

Ретроспектива другой сессии (дашборд/интерфейс AI_OS, 2026-07-27/28) и внешний
документ «Blueprint Agent System», принесённые Марией одним сообщением.

## Проверка легенды — Legacy-first Alarm, закрытие открытого пропуска

«Blueprint Agent System» — не новый внешний материал. Это тот же файл, что
уже был найден и явно помечен как непроверенный в
[[2026-07-25_external-assimilation-rick-heroes.md]]-цикле:
`БАЗА ЗНАНИЙ/ПРОМТИНГ/Blueprint 2026 v1.1_ Architecture for Reasoning-Model
Control.pdf` (плюс связанное семейство: Meta-Agent Law, Builder-Agent Spec,
Human Intake Agent Spec, Agent Patterns Library — та же папка). Тогда это был
один из двух пропусков Legacy-first Alarm, отложенный, не рассмотренный.
Сейчас он наконец получает разбор — цикл закрывается. FACT.

## Framing Drift — что подтверждается, что нет

**Подтверждается.** Сам класс ошибки реален и уже виден в файлах этого же
репозитория, не только со слов другой сессии:
[[2026-07-27_ai-os-interaction-principles.md]] прямо описывает, что сессия
«началась с сравнения инструментов (Graph/Canvas/Bases), затем сместилась к
сценарию понедельника Марии — и только из сценария выкристаллизовались
принципы». Это первое независимое проявление. Второе — второй раунд той же
сессии (07-28): вопрос «какие плагины поставить» сменился на «какой опыт
взаимодействия должен получить пользователь», и обнаружение, что центр
AI_OS ошибочно строился вокруг AI/Projects/Agents/Documents вместо
Жизнь→Работа→Проекты→Документы. Это не первое обнаружение проблемы в AI_OS —
`skills/idea-calibration.md` (строки 16-19) уже был расширен именно по следам
сессии 07-27 («без явного триггера здесь агент несколько раз садился
проектировать экран AI_OS до внешнего research»). Значит расширение триггера
Шага 0 идею поймало один раз, но не устранило её на более глубоком уровне —
внутри уже запущенного research агент всё равно осел на не том уровне вопроса
(инструмент вместо пространства, документ вместо опыта). Это делает Framing
Drift не гипотезой с n=1, а как минимум вторым независимым наблюдением того
же класса после уже предпринятой попытки исправления — ближе к Recurring
Pattern, чем к Hypothesis (Лестница обобщения).

**Не подтверждается.** Утверждение пасты «до этой сессии были: Execution
Drift, Ownership Drift, Tool Capture, Complexity Drift» как устоявшаяся
таксономия AI_OS — проверено: ни один из этих терминов не встречается в
CLAUDE.md или routing/registry.md как определённое понятие (кроме одного
поля `execution_drift: true` в триггере Architecture Review — это флаг, не
названный, описанный тип). Похоже, эти четыре названия — либо из другой
сессии/системы, либо реконструированы задним числом без сверки с файлами.
Использую как НЕ ЗНАЕМ, не как согласованный факт.

## Вывод по DECISION-рекомендации (AI_OS_BLUEPRINT.md, Intent Guardian, новый pipeline)

Не принимаю рекомендацию в предложенном объёме. Основания:

- **Extend before Create.** Ни один пункт предложенного Blueprint не вводит
  новую ответственность — только переносит и переименовывает то, что уже
  есть в CLAUDE.md (роли, pipeline, drift, validation, ownership — дословно
  список самой рекомендации). Framing Validation как проверка — да, новая;
  «Конституция» отдельным файлом и демотирование CLAUDE.md до Worker
  Contract — нет.
- **Simple Before Scalable + Minimal Sufficiency.** Самый лёгкий механизм,
  ещё не испробованный до конца — явное расширение `idea-calibration.md`
  Шага 1 (Problem Definition) и/или Disambiguate before Execute вопросом
  «формулировка всё ещё отвечает на исходные слова пользователя, или уже
  подменена инструментом/артефактом?» — это именно то, что описывает
  Framing Validation, без нового агента и нового файла-конституции.
- **Decision Monotonicity / SPEC для многосессионной работы.** Замена
  структуры авторитетных документов AI_OS (CLAUDE.md → Worker Contract +
  отдельная Конституция) — необратимая по духу правка с широким blast radius.
  Если Мария захочет её всё же сделать — нужен отдельный SPEC до начала
  (не в рамках этого лога), плюс Independent Validation (redefinition роли AO).
- **Лестница обобщения.** Два наблюдения пока внутри одного и того же
  рабочего потока (визуальный слой AI_OS), не на независимых проектах —
  граница как в [[2026-07-25_legacy-first-alarm-two-misses-same-session.md]]:
  «ближе к Recurring Pattern, чем к Hypothesis», но не полное подтверждение.
  Разумно поймать третий независимый случай (другой проект) прежде чем
  строить постоянную структуру под него.

**Открытый вопрос рекомендации, на который могу ответить сейчас (по
существующим фактам, не оставляю на решение Марии как настоящую развилку):**
Intent Guardian отдельным агентом или режимом — режимом/явным чек-пунктом
внутри существующего Reasoning Pipeline (шаг 2, Disambiguate before Execute),
не отдельным агентом. Отдельный агент оправдан, если тот же класс ошибки
проявится в третий раз независимо от текущего расширения — тогда это
Capability Design (Build), не раньше.

**Открытый вопрос про Home/Studio (Жизнь→Работа→Проекты→Документы vs
AI/Projects/Agents/Documents)** — не решаю здесь: это архитектурный выбор
интерфейса, а не факт, сравнимый по уже известным данным. Кандидат на
следующий раунд `2026-07-27_ai-os-interaction-principles.md`, не на этот лог.

## External Systems Assimilation — Blueprint Agent System

**Модель системы.** Строгая конвейерная архитектура для конструирования
GPT-агентов: Strategic Co-Architect → AGENT BRIEF → Builder → Instructions →
Agent → L0 Auditor → AUDIT PATCH → Builder (FULL REBUILD). Разделение слоёв
жёсткое, без коллапса; изменение агента — всегда полная пересборка Builder'ом
по BRIEF/AUDIT PATCH, никогда прямое самоизменение агента.

**Совпадает с AI_OS (adopt, уже есть в другой форме).** Слоевое разделение
≈ Capability Design (Build) → инструкции агента → исполнение → Architecture
Review; «нет самоизменения, изменения только через пересобирающий слой» ≈
Capability Evolution (кандидат готовится, действующая версия меняется только
после Independent Validation). Не нужно достраивать отдельно — уже
эквивалентно реализовано.

**Совпадение усиливает уже отложенный кандидат (повышает статус, не решает
за Марию).** «Traceability Requirement» (AGENT BRIEF → Instructions →
Behavior; потеря логики без явного audit — системная ошибка) — второй
независимый внешний источник, называющий то же самое, что
[[2026-07-25_external-assimilation-rick-heroes.md]] уже отметил звёздочкой
как сильнейшего кандидата («обязательная трассируемость происхождения
правила через инцидент»). Rick/Heroes и Blueprint Agent System не связаны
друг с другом — независимая конвергенция двух внешних систем на одной идее
поднимает её с «кандидат» до «стоит спроектировать в следующем цикле
Capability Design/Evolution», не строю здесь.

**Частично адаптируемо (не решено, кандидат).** Logic Type System (MODE /
CONTROL RULE / FLOW, запрет смешения типов) — конкретная техника, которой
сейчас нет в `skills/capability-creation-methodology.md`; потенциально
полезна при проектировании специализаций с явными режимами (например,
`fear_to_action_coach.md`). Не спроектирована, кандидат для следующего Build.

**Отклонено (reject).** Полная замена pipeline AI_OS ролями Strategic
Co-Architect/Builder/L0 Auditor целиком — избыточно: AI_OS уже покрывает
тот же функционал другими именами (Capability Design, routing/registry.md,
Architecture Review). Копирование ролей 1:1 нарушало бы Extend before Create.
GPT-builder-специфичные механики (Function Lock как защита от расширения
роли внутри одного диалогового агента, IDEA ANCHOR как разовая строка) —
специфика продукта другого масштаба (single-turn conversational agent), не
экосистемы из множества файлов и специализированных агентов.
